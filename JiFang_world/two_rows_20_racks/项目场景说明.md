# 双列20机柜机房仿真场景说明

更新日期：2026-10-22  
场景目录：`/home/zy/E_dog/JiFang_world/two_rows_20_racks`  
场景入口：`scene.xml`  
平台：Ubuntu 22.04 x64、MuJoCo 3.x。

## 1. 项目用途与范围

构建可独立复制和复用的机房环境，用于后续接入巡检机器人和相机，开展通道通行、门障碍交互、二维码定位与识别、巡检覆盖率等仿真实验。

当前场景包含两列20个机柜、差异化服务器配置、二维码、地面及建筑装饰、可手动控制的双扇门。当前版本不包含机器狗、巡检相机设备及ROS 2节点，后续可在此环境上集成。

## 2. 布局、坐标与尺寸

采用米为长度单位。世界坐标Z轴向上，X轴沿走廊从入口指向末端门，Y轴横跨走廊。L排位于+Y，R排位于−Y；两排设备正面均朝中央通道。两排机柜编号均沿+X依次递增。

| 项目 | 参数 |
| --- | --- |
| 机柜数量 | 左列L01–L10，右列R01–R10，共20个 |
| 单柜外形 | 沿走廊宽0.60 m × 深1.00 m × 高2.177 m |
| 单列长度 | 6.00 m，相邻机柜连续排列 |
| 中央通道净宽 | 1.20 m，指两排机柜正面外框之间距离 |
| 两列中心线 | Y=+1.10 m、Y=−1.10 m |
| 机柜正面外框 | Y=+0.60 m、Y=−0.60 m；设备及标签局部凸出以模型为准 |
| 机柜中心X坐标 | 0.30、0.90、…、5.70 m |
| 单柜安装容量 | 42U，1U=0.04445 m |
| 安装区底部高度 | Z=0.10 m |
| 末端门铰链平面 | X=6.65 m |
| 门框内净宽 | 1.30 m |

| 门开角 | 0–100°，朝+X方向的门后前室打开 |

地面格栅通过纹理表现，实际碰撞面为连续平面。场景保留顶侧梁、灯带及两端通道口，未设置遮挡全部总览视角的封闭屋顶。详细俯视布局见场景根目录的`floor_plan.svg`。

## 4. 二维码尺寸、位置与编码

每个机箱按占用U数配置标签：1U贴1张、2U贴2张、3U贴3张、4U贴4张。标签在设备正面靠左垂直排列，每张对应一个1U单元的中心高度。单张外形约4 cm × 4 cm，包含4模块白色留边；不在另一侧重复张贴。

二维码内容为字符串：

```text
x-y/z-高度
```

| 字段 | 定义 |
| --- | --- |
| x | 机柜编号，例如L01、R07 |
| y | 该机柜全部实际二维码从下往上的序号，从1开始；跨机箱连续编号，空槽不占序号 |
| z | 该机柜实际二维码总数，各机柜分别统计 |
| 高度 | 该二维码中心距地面高度，单位m，保留两位小数 |

实际示例：

```text
L01-1/38-0.12
L01-2/38-0.17
L01-3/38-0.21
R10-29/29-1.94
```

例如`L01-2/38-0.17`表示：L01机柜从下往上第2张二维码，该柜共38张，其中心高度约0.17 m。所有676个编码字符串唯一。

编码中的高度为两位小数近似值。需要精确投影或几何计算时，使用`equipment.json`中`qr_items[].position_world_m`的完整坐标；`height_m`与编码高度均已四舍五入。二维码法线见设备记录的`front_normal_world`。

## 5. 门控与碰撞

双扇门采用真实铰链刚体和位置执行器，可独立控制左右门。门扇及玻璃区域具有碰撞，可作为机器人通行障碍。

| 接口名称 | 含义 |
| --- | --- |
| `door_left_hinge`、`door_right_hinge` | 左右门铰链关节 |
| `door_left_motor`、`door_right_motor` | 左右门位置执行器 |
| `door_left_collision`、`door_right_collision` | 门扇碰撞几何 |
| `L01_collision`等 | 对应机柜的固定碰撞代理 |
| `L01_S01_qr_01`等 | 单张二维码几何，具体名称查`qr_items[].qr_geom` |

执行器控制量为弧度：0为关门，约1.74533为打开100°。两扇门都使用正开角表示打开。程序接入时应按名称查询执行器ID，再写入`data.ctrl`。

中文界面提供双扇开/关、单扇切换、角度滑块、保持当前位置、复位、视角选择和截图；O/C键分别开门、关门。墙面绿色开关是视觉示意，实际控制通过窗口或键盘完成，尚无机器人按压或鼠标点选墙面开关的逻辑。场景没有自动感应开门或自动关门机制。

机柜、地面、墙及门框具有碰撞。每柜使用一个固定实心碰撞代理；精细面板、线缆和二维码仅参与视觉渲染。空槽虽可见，但碰撞代理不支持探入柜内。

## 6. 启动与依赖

启动中文按钮界面：

```bash
cd /home/zy/E_dog/JiFang_world/two_rows_20_racks
./run.sh
```

启动官方原生查看器：

```bash
./open_native.sh
```

原生查看器没有中文门控窗口，可通过Control面板调节两个门执行器。中文查看器截图保存至场景目录的`captures/`。

场景提供`requirements.txt`，依赖MuJoCo（>=3.3且<4）、NumPy、Pillow、PyQt5。迁移到新环境后可安装：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
ROOM_PYTHON="$PWD/.venv/bin/python" ./run.sh
```

`ROOM_PYTHON`可指定Python解释器；MuJoCo位于其他包目录时可设置`MUJOCO_PYTHON_SITE`。二维码额外解码验证需要`zxing-cpp`。

## 7. 文件组织与迁移

| 文件/目录 | 用途 |
| --- | --- |
| `scene.xml` | MJCF场景入口：机柜、建筑、门、执行器 |

| `equipment.csv` | 设备简表，每行对应一个机箱，包含二维码数量与编码列表 |
| `floor_plan.svg` | 带尺寸俯视布局图 |
| `build_scene.py` | 可复现的场景生成器 |
| `room_viewer.py`、`runtime.py` | 中文交互窗口、物理推进及渲染代码 |
| `run.sh`、`open_native.sh` | 启动入口 |
| `requirements.txt`、`vendor/` | 依赖说明及附带二维码生成库与许可证 |
| `validate_scene.py`、`validation.json` | 自动验证脚本及验证记录 |
| `previews/` | 场景预览图 |
| `项目文档/项目场景说明.md` | 本说明 |

迁移时复制整个`two_rows_20_racks`文件夹。XML与纹理使用相对路径，不依赖原单柜场景目录。单独集成场景至少需保留`scene.xml`、`assets.xml`及完整`assets/`；建议同时保留元数据，便于查询二维码真值。

生成其他随机布局的示例：

```bash
python3 build_scene.py --seed 20261023 --output /完整路径/另一组场景
```

生成器输出模型、纹理、元数据及布局图；新目录要运行按钮界面，还需复制查看器、运行代码、启动脚本与依赖文件。生成器会覆盖目标目录中的生成文件，应为需要保留的布局选择独立输出目录。预览和验证记录需重新生成。

## 8. 验证结果与使用边界

本版已有验证记录：20柜布局及1.20 m通道尺寸正确；门反复开关、单扇控制和保持角度通过；直径0.36 m测试探针在关门时被阻挡，开门后可通过。模型及资源复制到临时目录后可独立加载，同种子重建结果一致。

676张二维码源图片均通过解码；每柜抽取一张二维码进行近距离渲染解码，共20张均通过。该检查证明编码及纹理有效，不代表任意相机位置、焦距或距离下全部二维码都能识别，也不等同于实物识别率验证。

运行基本验证：

```bash
python3 validate_scene.py --check-rebuild
```

后续相机实验可使用二维码精确坐标作为真值，按机柜编号和二维码序号统计漏检、重复检测及巡检覆盖率。相机成像、机器人运动、ROS 2通信与实际设备误差应在集成阶段分别补充。
