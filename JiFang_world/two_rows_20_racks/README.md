# 双列 20 机柜机房：独立场景与手动门

这是一个可整体复制、独立复用的 MuJoCo 场景。包含两列各 10 个机柜、1.20 m 中央通道、随机设备与二维码、实体双扇门及中文按钮窗口。**不包含机器狗、巡检相机设备或 ROS 节点。**

## 启动与开关门

```bash
cd /home/zy/E_dog_sim/JiFang_world/two_rows_20_racks
bash run.sh
```

启动不需要 sudo。脚本依次使用 `EDOG_VENV`、已激活的 venv、从脚本目录向上查找到的最近 `.venv`；所有 Python 依赖均从选中的环境加载。第一次安装请在项目根目录执行 `python3 -m venv .venv`，再执行 `.venv/bin/python -m pip install -r requirements.txt`。

窗口按钮：

- **开门（双扇）／关门（双扇）**：控制两扇门从 0°到 100°之间平滑运动。
- **左门切换／右门切换**：可独立操作单扇门。
- **保持当前位置**：将门的目标角度设为当前角度。
- **角度滑块**：手动设置两扇门的目标开角。
- **复位场景**：门恢复关闭状态。
- **视角选择**：通道入口、门口近景、俯视、外侧总览及自由观察。自由观察时拖动旋转、滚轮缩放。
- **O／C 键**：分别开门、关门。截图按钮保存到本目录 `captures/`。

门上有把手，旁边有可见的墙面绿色开关示意。**实际控制通过窗口按钮或键盘完成，墙面开关不包含鼠标拾取/机器人按压逻辑。**

界面将物理推进和 OpenGL 渲染放在后台线程，静止时复用画面，避免长走廊模型阻塞按钮响应。

若只使用官方独立 `simulate`（同样加载 venv，另需安装独立程序）：

```bash
./open_native.sh
```

原生程序没有中文按钮窗口；可在其 Control 面板调节 `door_left_motor`、`door_right_motor`。Control 值单位为**弧度**：0 关门，约 1.74533 对应 100°。

| 每行长度 | 10×0.60=6.00 m，机柜相邻排列 |
| 两排正面净距 | **1.20 m**，不是两排中心线间距 |
| 两排中心线 | y=+1.10 m、y=−1.10 m，间距 2.20 m |

世界坐标 Z 向上，X 沿走廊从入口指向门，Y 跨越通道；L 排位于 +Y，R 排位于 −Y，两排设备正面均朝通道。俯视图见 `floor_plan.svg`。

地面格栅为视觉纹理，碰撞地面是连续平面。背景保留两端通道口和顶侧梁/灯带，便于从外部查看，不建立遮挡所有总览的封闭屋顶。末端门后的通道口通向场景外部。

## 随机配置与二维码

默认随机种子为 **20261022**，同一种子重复生成得到相同布局。20 个机柜的设备/空槽组合各不相同：

| 项目 | 本版数量 |
| --- | ---: |
| 安装设备 | 288 |
| 1U / 2U / 3U / 4U 设备 | 68 / 86 / 81 / 52 |
| 已贴二维码 | 676 |
| 有设备但缺少二维码 | 0 |
| 空置安装空间 | 合计 149U |

每个柜壳保留 42U 内部安装范围，随机混排 1U–4U 设备与空槽；L04、R08 配置更稀疏。空置区域不放服务器，也不放二维码。这里保留全部 **20 个柜体**，“缺设备”通过柜内空槽表达。

每台已安装设备按自身 U 数张贴二维码：1U=1张、2U=2张、3U=3张、4U=4张。当前共 676 张二维码，等于所有已安装设备的 U 数总和；空槽不贴二维码。二维码垂直排列在设备正面靠左，单张外形 4×4 cm，含 4 模块白色留边。

二维码内容采用新的调试友好字符串格式：**`x-y/z-高度`**。其中 `x` 是机柜编号（如 `R01`、`L07`），`y` 是该机柜从下到上的二维码序号（从 1 开始），`z` 是该机柜二维码总数，`高度` 是该二维码对应 1U 单元中心距地面的高度，单位 m，保留两位小数。例如：`L01-1/38-0.12`、`R10-29/29-1.94`。

每个机柜内部的 y 序号独立从 1 开始；因此不同机柜可能出现相同 y/z/高度，但 `x` 区分机柜。所有二维码值和位置见 `equipment.json`、`equipment.csv`。

材质与外观包括黑色设备、银色框架、黄色端口、蓝色线缆、指示灯和局部空槽。随机化主要作用于设备 U 数、空槽、标签缺失、细小面板深度及线缆配置；柜体尺寸固定。

## 物理与门接口

机柜、地面、墙和门框具有碰撞；每个柜体采用一个固定实心碰撞代理。精细面板、孔洞、线缆、二维码均只做视觉装饰，不产生大量碎小接触。空槽是视觉可见的柜内空位，柜体碰撞代理不支持探入柜内。

门是**真实铰链刚体**，由两个位置执行器控制，门扇玻璃区域也包含实体碰撞，不会穿透。没有自主感应开门或自动关门逻辑，只有手动命令改变目标角度。

| 名称 | 用途 |
| --- | --- |
| `door_left_hinge` / `door_right_hinge` | 两扇门的铰链关节 |
| `door_left_motor` / `door_right_motor` | 位置执行器，控制量为弧度 |
| `door_left_collision` / `door_right_collision` | 门扇实体碰撞几何 |
| `<柜号>_collision`，如 `L01_collision` | 柜体固定碰撞代理 |
| `<设备编号>_qr`，如 `L01_S01_qr` | 该设备二维码几何 |

两个关节都用正开角表示向后方打开，右门的关节轴方向与左门相反。后续程序可直接加载 `scene.xml`，向 `data.ctrl` 中对应执行器写入 0–1.74533；无需依赖中文查看器。

| --- | --- |

| `assets/` | 全部本地 PNG 纹理，包括真实二维码 |

| `equipment.json` | 所有设备的编号、U 数、高度、二维码存在状态、世界位置与法线 |
| `equipment.csv` | 同一设备表的简版，便于后续分析 |

| `build_scene.py` | 可复现生成器 |
| `vendor/` | 附带的 python-qrcode 8.2 及第三方许可证 |

| `venv.sh` / `requirements.txt` | 独立环境选择工具／Python 依赖清单 |
| `validate_scene.py` | 布局、开关门、碰撞及可搬移性检查 |
| `validation.json` / `gui_validation.json` | 本机验证记录 |
| `previews/` | 开门、关门、门口、俯视及总览预览 |

**移动时直接复制整个 `two_rows_20_racks` 文件夹。** XML 和纹理均使用相对路径，没有指向原单柜项目的 include、纹理路径或符号链接。运行时只需要通用 MuJoCo/Python/Qt 依赖，不需要原机柜目录。

新电脑可在虚拟环境安装：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
bash run.sh
```

脚本会自动发现上面的 `.venv`，无需再次指定解释器。使用其他位置的环境时，执行 `EDOG_VENV=/环境目录 bash run.sh`。请一并复制本目录的 `venv.sh` 和 `requirements.txt`，保证独立运行。

生成另一组布局：

```bash
python3 build_scene.py --seed 20261023 --output /完整路径/另一组场景
```

上述命令生成 XML、纹理、元数据和尺寸图；若要在另一目录使用按钮界面，请一并复制 `room_viewer.py`、`runtime.py`、启动脚本和依赖说明，或先复制整个文件夹再在复制品中运行生成器。不要在需要保留的布局目录直接换种子，因为它会覆盖生成文件；预览和验证记录也不会自动更新。

## 验证结果

- 两排各 10 柜，正面净距实测模型值为 1.200000 m。
- 20 种不同设备/空槽组合，1U–4U 均存在，缺码设备不产生二维码几何。
- 门反复开关、单扇控制及保持角度正常；完全打开时不撞门框。
- 直径 0.36 m 的动态探针：关门时被门阻挡，开门后通过门口且不接触门扇。探针仅在验证时临时添加，不在交付场景里。
- 全部 676 张二维码原图可解码；20 个机柜各取一个二维码的近距离渲染图均解码通过。
- 将 XML 与资产复制至另一临时路径，成功独立加载；同一种子生成的文件内容一致。
- 中文按钮窗口的开门、单扇关门、保持、复位、视角切换已通过操作检查。

基本检查：

```bash
python3 validate_scene.py --check-rebuild
```

二维码额外检查需安装 `zxing-cpp`；未安装时会明确跳过这一可选项。若 MuJoCo 包单独安装在其他环境，可设置前述 `MUJOCO_PYTHON_SITE`。
